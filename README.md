# Platypus

**A byte-level language model trained on ten text domains in turn, with a symbolic memory and sleep cycle beside it that extracts planted template facts, joins them, learns which relations compose, and teaches the model the results.**

The results log is [`RESULTS.md`](RESULTS.md).

Current build: **cg27a with interleaved distillation**: from 11 November the build's defaults include interleaved distillation of stored facts into the trunk (question rows writing the MLP output weights only, a question pool of up to 2000 facts), chunked probe evaluation and a GPU cache release after each sleep phase (the sleep peak fell from 70 to about 50 GB), the Gaussian drift readout, a planted **rule world** (families and org charts whose facts obey composition rules; `inf_rule_world 12`) and retrieval-augmented answers with a cited source (`inf_jx_rag`); older presets pin the previous defaults so they reproduce their runs. GPU presets: `configs/presets/cg27a.env` (full build, three passes - distillation has so far been run through pass 1 only, so passes 2-3 with it are untested); `configs/presets/cg27a_distillcap_pass1.env` (the reference distillation run, pass 1; seed 4, seed 5 via the notebook's `SEED` line); `configs/presets/cg27a_distillctl_pass1.env` (its control: no question rows trained); `configs/presets/cg27a_distillak_pass1.env` (soft anchor, with the composition and latent-chaining readouts); `configs/presets/cg27a_rag_pass1.env` (retrieval-augmented answers, operator algebra on the rule world; readouts only); `configs/presets/cg27a_relmod_pass1.env` (the relational module, readout only); `configs/presets/cg27a_relwrite_pass1.env` (the relational module's verified conclusions written into the question pool - one model change; the run in progress, seed 4). ## What it is, in one paragraph

A 171M-parameter language model (byte vocabulary, hashed 2/3/4-gram embeddings, one causal local-filter block, three gated delta-rule mixer blocks, one output head per domain) is trained on ten Pile domains one after another — Gutenberg, Wikipedia, ArXiv, PubMed, FreeLaw, GitHub, StackExchange, USPTO, DM Mathematics, EuroParl — three passes over the schedule, about 6.5 MB of real text per visit. Its forgetting is kept low by replaying its own generated text in each domain's style with stored teacher targets, by Fisher-whitened (K-FAC) updates, and by a small amount of private capacity per domain. After each visit a **sleep phase** runs over what was read. It stores every real sentence that names two capitalised words (tens of thousands per visit), pairs stored sentences by shared names and by a small JEPA head, keeps a pair only if each sentence makes the other cheaper for the model to predict, and replays the accepted splices into the weights under a brake. Alongside the real text, the harness plants a small set of template facts about invented people — `Xaquimon works with Zotarbel.`, six relations with a paraphrase each, 30 copies per fact per pass — as a measurement instrument, and from 11 November a **rule world**: twelve families and twelve org charts (`X is a child of Y`, `X is supervised by Y`) whose composite facts (`is a grandchild of`, `is overseen by`) are planted for half the people and held out for the rest, so that only a rule can supply them. A hand-designed reader pulls these out, joins facts that share a name into two- and three-hop conclusions (`So A is connected to C.`), checks that the sources are still present, and teaches the conclusions to the model by replay and by closed-form MEMIT-style edits to one MLP matrix. A separate **fast store** — a hash table of logit corrections keyed by names found in the text — answers questions about these facts directly, and a protocol releases facts from the store once the weights answer them alone, deletes them after a grace period, and writes them back if the weights lose them. From 11 November the recorded facts are also **taught to the trunk while it reads** (interleaved distillation): four question rows about stored facts, in seven wordings the system writes itself (none of them a test wording), are added to each training step and update only the blocks' MLP output weights; a fixed fifth of the facts, chosen by a hash, is never taught and serves as the control. A **relational module** in sleep (from 11 November, preset only) learns a code for each name and an operator for each relation from the facts the reader recorded, without being told which relations compose; a rule (`child o child -> grandchild`) is kept only if the product of two operators beats fits on shuffled facts and the chain predicts the composite facts the reader recorded. In `cg27a_relwrite` the conclusions of verified rules, drawn through stored premises only, join the question pool, so the trunk is taught facts nobody stated. The reader only works on template-shaped facts, so every recall figure in this README is on the planted set or, for the distillation rows, on recorded facts in the same six relation phrases (38-60% of them planted); whether the real-text dreams do anything measurable is an open control.

**The trunk does not infer anything.** The reader and the join are symbolic; the relational module's rule discovery is learned but runs beside the trunk, in sleep. The model takes part in three places: it learns the real text, it judges proposed pairs (a pair passes if each sentence makes the other cheaper to predict by at least 2 bits, or by the 97th percentile of random pairs if that is higher), and it is taught the conclusions that survive. Tests on 11 November confirm this division of labour: facts taught into the trunk are recalled from it, but the trunk does not combine two of them into a conclusion it was never given, and neither does a JEPA-style predictor trained on the trunk's own name codes (see "What has been measured"). Composition happens in the sleep layer, which answers with its sources or abstains; what the trunk can do is learn the conclusions the sleep layer writes (first readings: 0.75 from the weights against 0.00 held back, tiny numbers; see the table). The JEPA index's proven role is retrieval: finding the stored sentence a question needs, including in wordings never written anywhere. With `inf_jx_rag` (on by default) that sentence is put in front of the question and cited as the answer's source: it lifts answers among 20 candidates, not open-ended answers.

## What it is not

- **Not a system that learns facts from real text.** Every recall, abstention, revision and consolidation figure in this repository is on planted template sentences. The dream path does read real text — splice cues and partners come from the stored real sentences, and about half the sleep replay rows are such splices (`inf_mix_dream 0.5`) — but no gain from them has yet been isolated from the rest of sleep. On 262 Re-DocRED Wikipedia paragraphs the reader's entity precision is 0.49 and its relation pairs are gold at the rate of chance (0.28 vs 0.29). The trunk shows no relational signal on those pairs either (AUC 0.45–0.50, local). See `tools/redocred_reader_test.py`. Scored against all 4,726 gold relations of the embedded benchmark, the reader recovers 36 (0.8%), and its filters and the seen-twice rule leave about none (`tools/reader_audit.py`): it takes a clause's two rarest words as the arguments, so well-known entities are never arguments and names of several words are split. A count-based alternative, tested offline only, recovers 325 (see the table).
- **Not a model that composes facts in its weights.** Given both premises of a chain and no written conclusion, two-hop recall from the weights is 0 of 11 locally and 0.17 on the GPU (0.95 with the premises in context <!-- not yet in RESULTS.md: add the source run or remove -->). The local figure is expected and says little: implicit two-hop composition appears only after long training well past memorisation (Wang et al. 2024), and the local harness is a 512-wide model trained 400 steps per visit; its 400-step ceiling test memorised without composing, too short to judge. The GPU figure is a weak-powered observation from ordinary training. The designed test — `CEILING LONG`, 2,000 steps with in- and out-of-distribution chains — has not yet returned a GPU result (it was the end-of-run readout that ran out of memory; it now runs last, in low-memory mode). Open-ended production of a held-out-wording two-hop answer from the weights alone is 0.00 in the configured build (0.04 in shadow experiments). Interleaved distillation does not change this: on the GPU (seeds 4 and 5) conclusions in the weights come from the closed-form edits (0.47-0.69 with them, 0.08-0.18 with them subtracted), and never-taught conclusions whose two premises were both taught are at 0.00-0.08 with the edits subtracted (6-14 questions). With every 4th planted chain never concluded, stored, replayed or edited (`inf_kgx_hold 4`), the trunk composes **0.00** of the held-out chains whose two facts it was taught, including those where it answers both premises (GPU, seed 4: 5-11 chains, 3-7 with both premises answered, in two runs). Composition is done instead by the relational module in sleep, and the trunk is taught its written conclusions (see the table). Bridge anchoring (after BRACE, NeurIPS 2026: one fixed attribute of the bridge entity added to both hops' question rows) is inconclusive: the planted bridge names occur only in their own chain, so the attribute had to be invented, and only 2 anchored chains became testable. A JEPA-style composer trained on the chains the system concluded answers the unconcluded ones at 0.00-0.29 on 1-11 chains (0.09 at 11; chance 0.05): it memorises its training chains.
- **Not continual learning without access to the data.** The "closed loop" (passes 2 and 3) still draws the real training batch at every step. The real-text cross-entropy is multiplied by zero; the batch is instead encoded by a frozen copy of the model into per-token key/value traces, decoded back to bytes, checked for consistency with the trace, and the decoded bytes train the student. The fast store reads the raw batch directly (`cd_store_text`). With `PLATYPUS_HINTS=1` (the default) 2–8% of the true bytes are also stored and forced. The traces for an 8-byte segment are per-token vectors of width 1088 across three blocks: far larger than the bytes they encode.
- **Not benchmarked against other methods.** Internal comparisons exist and are in [`docs/README-full.md`](docs/README-full.md): dream rehearsal on and off (local, October: forgetting +0.228 without it, +0.021 with it), private capacity on and off, plain against Fisher-protected replay at matched doses, the closed-loop bounds on the GPU (second pass learns nothing 1.739 BPC / verified replays only 1.474 / real text again 1.468), trunk replay against none on the small model, sleep against quiet rest, the oracle options on and off, and (local full runs, 11 November) dream replay against none with distillation off: forgetting at the end of the run -0.005 with replay against +0.071 without (final BPC 2.415 against 2.484), and at half width without replay +0.32 at the end of pass 1; and the system has run at two sizes, the five-domain local harness and the 171M GPU model. What is missing is a comparison with established methods — EWC alone, stored-example replay, per-episode adapters — on the current build and schedule, and any public benchmark result. Pass-1 headlines now have two GPU seeds (1 and 2, 9 November); the three-pass numbers have one. Local results differing by less than about 0.15 in recall or 0.017 in BPC are seed noise.
- **Not a trained hippocampus.** The fast store is a dictionary: a regex (or the "two rarest words" rule) finds a name, the name selects a bank of rows, and the rows add corrections to the output logits. "Exact recall" and "abstention on unknown names" are properties of a lookup table.

## What is of merit

The parts most likely to be useful to someone else are infrastructure, not the memory claims:

- **`layers.py`**: a gated delta-rule mixer with five interchangeable solve paths — a Triton kernel (flash-linear-attention), a blocked WY solve with a hand-derived backward pass, a chunked state-passing form, a windowed form and a dense fallback — chosen per head dimension by a start-up benchmark. Memory state can be carried across windows as a dense matrix, as factored `(U, K)` write terms, or as fixed-size slot buffers. The mixer reads before it writes (`S_{t-1} k_t`, no separate query) and uses a diagonally preconditioned write key.
- **`protection.py`**: K-FAC Fisher factors per block, batched coupled Newton–Schulz inverse square roots, Muon via Gram Newton–Schulz, Gauss–Newton (VarPro) head refits, gradient-noise-scale estimation with Neyman allocation between replay and real rows.
- **`conduit.py`**: byte-by-byte generation under captured CUDA graphs with static buffers and a parameter-pointer signature check; incremental generation that is arithmetically identical to the full-prefix pass.
- **`ngrams.py`**: hashed n-gram tables with independent hash families, a lazy per-row Adam, and absolute-discount back-off count sketches.
- **`inference/closed_form.py`**: MEMIT-style least-squares edits with the sentence-frame direction removed from the keys, every edit re-solved against its current key each sleep, kept under a loss brake and a cumulative budget.

None of these is a research result; each is a careful implementation of 2017–2026 methods. The protocol-level ideas that are plausibly new — re-keying edits every sleep, release → ghost → reinstate timed by half-life regression, a replay signal gated on reproducing the encoder's own trace — are each tested on one or two seeds, on templates, without a baseline.

## Known defects

- The fast store is installed by replacing `Model.forward` and `Head.forward` at import time. It should be an explicit wrapper.
- The package is a 21k-line single-file program split into 58 modules: names are wired across modules by `_LATE` tables and `common._set_global`, module-level state is rebound at run time, and the config has ~670 fields of which most are off. The code carries dormant buffers and options from earlier designs (per-unit affinities, impedance gates, a differentiable meta-controller). Brakes are thresholds, not zero-tolerance: 0.015 BPC for closed-form edits, 0.03 for dream replay, 0.005 for consolidation.
- 179 `except Exception` handlers print and continue. A run-level `FAILURES:` count was added in `eval-fix`, and `scripts/check_undefined.py` (pyflakes minus `_LATE` names) now runs in CI after four undefined names were found behind off-by-default options.
- Tests check that modules import and link, that no name is undefined, and that scripts parse their fixtures; nothing tests model behaviour.
- Variable naming (`rf9n_`, `mo9n_`, `EN9_`) and 300+ lines over 200 characters make the sleep and edit code hard to review.

## Direction

The standing goal (8 November 2026) is to replace the trained parts of sleep with simple local rules: a slow-feature layer on the trunk in place of the trained JEPA selector, and eventually a learned reader in place of the hand-designed one, with the fast store kept to one job — making facts met far apart adjacent for replay. It is pursued as rungs, each with a pass criterion, recorded in [`RESULTS.md`](RESULTS.md).

- *Rung 0 — closed-form slow features vs the trained JEPA.* Ties on held-out-wording retrieval (0.15 vs 0.12), loses in the written wording (0.07–0.15 vs 0.38–0.42); names alone beat both (0.70–0.90). Local.
- *Rung 1 — slow features on the trunk.* Met by a closed-form SFA fit re-solved each sleep, which the latent judge and selector comparison already use (0.17 / 0.38 top-1 in unseen wordings). The online version — a small head trained by prediction, variance and decorrelation terms, plus three alternative rules — did not reach the closed-form solution in eight attempts and is parked. The per-sleep fit serves the purpose; the "online, local rule" part of the goal remains open.
- *Rung 2 — a latent judge (SFA cosine) for dream pairs.* Matches the byte judge on known-linked controls (AUC 0.92–1.00) at about 1 ms per pair against 20–40 ms, but the controls share a bridge name by construction; on real proposals its agreement with the byte judge is AUC 0.64–0.69. *Rung 2b*, a relational signal on real prose from any latent readout: negative.
- *Rung 3 — the name channel.* The lead described under Open questions.
- *Rung 4 — the reader (now the priority, 11 November).* Against the benchmark's gold relations the reader recovers 0.8%. A frame encoder trained by a joint-embedding objective did not learn the relation (0.40 vs 0.44 for the connector words). A fast channel that counts short common word sequences - frames - and reads what varies between them as fillers recovers 6.9% (offline); building it into the store's reader is the next build.

Read strictly, the latent signals so far (JEPA, SFA, latent judge) match TF-IDF on names wherever a shared rare name exists and are at chance where none does.

## Open questions, in order

1. Does anything here beat EWC alone, stored-example replay or per-episode adapters on the same ten-domain schedule? Not yet run (the internal ablations under "Not benchmarked" compare the system's own parts, not other methods).
2. Do JEPA-chosen dreams beat random dreams on recall or forgetting? Control pending. (As a retrieval key the JEPA index is clearly useful; see the table.)
3. Is the temporal gradient consolidation or replay count? It holds on a second seed and among never-edited conclusions; replays per conclusion are not yet counted.
4. Can the weights answer in a wording they were never taught, open-ended, above 0.00? **For single recorded facts, yes, on two GPU seeds:** taught by interleaved distillation, 0.6-0.7 after a few visits in untrained wordings against 0.01-0.06 for never-taught facts. For conclusions, not yet (see 7). Earlier leads in `RESULTS.md`: a name-keyed memory (shadow, 0.15 with oracle answer positions; 0.06–0.09 locally with a learned gate). Ruled out: a ROME-style subject edit, and replaying facts in varied wrappers.
5. Can any reader extract relations from real prose above chance? Until it can, nothing downstream applies to real text. The current reader: 0.8% of the benchmark's gold relations; a count-based fast sequence channel, offline: 6.9% (59% of what one-sentence reading allows). Pronouns and cross-sentence reading (88% of the gold relations) are untouched.
6. Does the closed loop work with the training batch removed — traces from pass 1 only, no `cd_store_text`, no hints, store off for BPC? That experiment is not implemented.
7. Can the trunk compose two taught facts into a conclusion it was never taught? **No, at this scale:** 0.00 on held-out chains, including chains whose premises it answers; a JEPA-style composer does not generalise either. Bridge anchoring could not be tested properly on planted names. Composition is left to the sleep layer, where a relational module now discovers composition rules from the recorded facts against a shuffled null (GPU: both rule-world rules, no false ones).
8. Can facts be written where old domains do not read, to remove the +0.02 BPC cost? A null-space projection cannot work at this width (see above). Tested locally: fact units - new MLP units, one per new fact, keyed on its question context and the only weights the question rows train. With the inputs centred they are about 2x selective, but they did not learn the facts (taught recall 0.00 against 0.11); the cost stays.
9. Does the trunk answer better, open-ended, with the JEPA-retrieved sentence in front of the question, and is the cited source right? Among 20 candidates, yes (0.72 -> 0.86; 0.41 -> 0.56-0.67 in the `cg27a_rag` runs); the cited source is right 0.85-0.97; open-ended, no (0.10-0.21 -> 0.08-0.15).
10. Do conclusions the system inferred itself, never stated in its text, consolidate into the weights? First reading, yes (0.75 taught vs 0.00 held back, 4 and 2 facts; GPU, `cg27a_relwrite`, run in progress). Needs the full run and a second seed.

## Getting started

Python 3.10+, PyTorch with CUDA, `datasets` (for `monology/pile-uncopyrighted`), `scipy`. Optional: `flash-linear-attention` for the Triton kernel; the code falls back to a pure PyTorch solve.

```bash
pip install torch datasets scipy
python -m platypus                     # from the repository root
```

In Colab use `colab/platypus_gpu.ipynb`, which runs `scripts/run_gpu.sh`. A three-pass run takes four to five hours on one large GPU. `scripts/run_local.sh` runs a five-domain CPU harness. Presets are in `configs/presets/`; the `PLATYPUS_*` switches are listed in `platypus/__main__.py`. Deployment, manifests and the release checklist are in [DEPLOY.md](DEPLOY.md).

Code layout, configuration options, log-line glossary, history and references: [`docs/README-full.md`](docs/README-full.md).
